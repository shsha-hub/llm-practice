# Day 04 미니 프로젝트: 버려도 될까?

자연어로 물건의 재질과 오염 상태를 설명하면 관련 생활폐기물 규칙을 찾고,
근거가 있는 배출 방법만 안내하는 로컬 검색·RAG 앱입니다.

> **주의:** 
> 품목별 기준은 환경부·부산광역시 자료, 요일·시간은 부산진구가 2025년 2월 19일 게시한 안내를 사용합니다. 
> 부산진구 공식 요일표에는 2021년 12월 25일 시행이라고 표시되어 있습니다.
> 공동주택은 관리사무소의 별도 기준을 우선하고, 실제 배출 전에는 공식 출처의 최신 내용을 확인하세요.

## 수업 내용과 연결되는 지점

- 임베딩과 코사인 유사도로 표현이 다른 질문을 의미 검색
- 임베딩 모델 또는 규칙 데이터가 바뀌면 인덱스 자동 재생성
- bi-encoder의 상위 후보를 cross-encoder로 재정렬
- 검색된 규칙만 로컬 LLM에 전달하는 근거 기반 RAG
- 골든셋으로 `Hit@1`, `Hit@3`, `MRR` 측정

채용공고 추천과 달리 이 프로젝트는 `동·재질·오염 상태`를 구분해 배출 규칙을 찾습니다. 
부산진구의 20개 동을 두 권역으로 나눠 품목 검색 결과에 해당 동의 요일과 시간을 결합합니다. 
최상위 검색 점수가 낮거나 공식 표에 세부 일정이 없으면 추측하지 않고 답변을 보류합니다.

## 실행

저장소의 가상환경에 패키지가 설치되어 있다면 다음 명령만 실행합니다.

```bash
cd /home/student/llm-practice/c5-slm
.venv/bin/streamlit run day04/app.py
```

가상환경을 활성화한 상태로 `day04` 폴더 안에 있다면 아래처럼 실행해도 됩니다.

```bash
cd /home/student/llm-practice/c5-slm/day04
streamlit run app.py
```

처음 선택한 임베딩 모델은 Hugging Face에서 다운로드되므로 시간이 걸릴 수 있습니다. 
이후에는 모델 캐시와 `day04/indexes`의 임베딩 인덱스를 재사용합니다.
모델을 바꾸거나 `data/waste_rules.jsonl`을 수정하면 fingerprint가 달라져 새 인덱스를 만듭니다.

## 로컬 RAG 사용

의미 검색 자체는 Ollama 없이 동작합니다. 
생성형 답변까지 실험하려면 별도 터미널에서 Ollama를 실행하고 모델을 준비합니다.

```bash
ollama serve
ollama pull qwen2.5:3b
ollama create waste-rag -f day04/Modelfile
```

앱 사이드바에서 `로컬 LLM으로 답변 생성`을 켭니다. 
Ollama 연결에 실패하면 검색된 규칙 원문으로 만든 구조화 답변으로 자동 전환됩니다.

## 검색 성능 평가

임베딩 검색만 평가합니다.

```bash
.venv/bin/python -m day04.evaluate
```

한국어 cross-encoder 재정렬까지 비교하려면 다음과 같이 실행합니다. 
모델이 크므로 CPU에서는 시간이 걸릴 수 있습니다.

```bash
.venv/bin/python -m day04.evaluate --with-reranker
```

`data/golden_queries.jsonl`에 어려운 표현과 정답 규칙 ID를 추가하면 프로젝트만의 평가셋을 확장할 수 있습니다. 
임베딩 모델을 비교하려면 다음처럼 실행합니다.

```bash
.venv/bin/python -m day04.evaluate --embedding-model BAAI/bge-m3
```

현재 15개 골든 질의를 `ko-sroberta`로 측정한 기준 결과는 다음과 같습니다.

| 파이프라인 | Hit@1 | Hit@3 | MRR |
|---|---:|---:|---:|
| 임베딩 검색 | 0.600 | 1.000 | 0.767 |
| 임베딩 + 한국어 reranker | 1.000 | 1.000 | 1.000 |

공식 문구에는 유사한 예외와 주의사항이 많아 1차 검색의 구분이 더 어렵지만,
정답이 모두 3위 안에 있어 재정렬 효과를 명확히 확인할 수 있습니다.
데이터나 모델을 바꾼 뒤에는 이 수치를 새로 측정해야 합니다.
